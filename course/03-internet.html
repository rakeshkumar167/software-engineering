3. How the Internet Works: IPs, DNS, Routing

A giant network of networks that agree on common rules (protocols).

✉️ Start here: the postal system

A story You want to send a 500-page book to a friend in another country. The post office won't take it as one giant parcel. So you:
1️⃣ Tear it into 100 small envelopes, number them ("page group 7 of 100").
2️⃣ Write the friend's address and yours on each.
3️⃣ Drop them in the mail. Each envelope passes through sorting offices; each office only knows "which way to the next office?".
4️⃣ Envelopes may take different routes, arrive out of order, and one might get lost.
5️⃣ Your friend sorts them by number, notices #43 is missing and asks you to resend.

The internet works exactly like this. Envelopes = packets. Addresses = IP addresses. Sorting offices = routers. The "resend #43" logic = TCP.
  YOU                                                        SERVER
 ┌────┐   packet 1 ─► [router A] ─► [router C] ─────────────► ┌────┐
 │    │   packet 2 ─► [router A] ─► [router B] ─► [router D] ►│    │
 │    │   packet 3 ─► [router A] ─► [router C] ─────────────► │    │
 └────┘                 (different paths, reassembled in order)└────┘

Part 1: IP addresses (the house number)

Every device on a network has an IP address, like 203.0.113.7. But a house has many rooms, so an address alone isn't enough: add a port, the room number. Web server lives in room 443 (HTTPS), mail in room 25.

  203.0.113.7 : 443
  └── building ┘ └ room (which program?)
  • Public IP: your home's street address that the whole world can send to.
  • Private IP (192.168.x.x): inside your home, like "bedroom 2". Your router does NAT, acting as the front desk that sends replies to the right bedroom.
  • 127.0.0.1 = "me, myself" (localhost). You're knocking on your own door.

Part 2: DNS (the phone book)

Humans remember google.com; machines need 142.250.80.46. DNS looks up the number for the name. Follow one lookup:

Your browserDo I already know example.com? ...no. Hey resolver (ISP), where is example.com?

ResolverNot in my notebook. Root server, who handles ".com"?

Root serverAsk the .com servers, here's their address.

.com serverexample.com? Ask ITS own name server, here it is.

example.com's name serverIt's 93.184.216.34! (Cache this for 5 minutes.)

The resolver remembers the answer for the TTL (time-to-live). That's why DNS changes sometimes take hours to "propagate": everyone's notebook has the old number until it expires.

Part 3: Routing (asking for directions at every corner)

No router knows the whole route. Each looks at the destination IP, checks its table ("anything for 93.x.x.x goes via my uplink B"), and passes the packet on. See it yourself:

$ traceroute example.com
 1  192.168.1.1     (your home router)
 2  10.20.0.1       (your ISP)
 3  ...             (more hops)
12  93.184.216.34   (destination!)
Brain powerPackets can arrive out of order, and some vanish. So how does a video call or a downloaded file arrive intact? (TCP numbers packets, reorders them, and re-requests missing ones. Video calls often use UDP instead: a late frame is useless, so they skip resending.)

Everything together: typing a URL

  1. DNS:   "what's the IP of example.com?"        → 93.184.216.34
  2. TCP:   open a connection to 93.184.216.34:443  (handshake)
  3. TLS:   agree on secret keys                    (the "S" in HTTPS)
  4. HTTP:  GET /  →                                 request
  5.        ← 200 OK + HTML                          response
  6. Browser draws the page; repeats for images/CSS/JS

There are no Dumb Questions

Q: Why do we have both IPv4 and IPv6?

IPv4 has only ~4.3 billion addresses, and we ran out (phones, TVs, fridges...). IPv6 has an absurdly large supply: 2001:db8::1. Both are in use now.

Q: Is "the internet" the same as "the web"?

No. The internet is the network of networks (the roads). The web (HTTP + HTML pages) is just one thing driving on it. Email, games and video calls use the internet too.

Q: Why does ping show a time like 25 ms?

Round-trip time for a tiny packet. Light in fiber takes real time: crossing an ocean costs ~70 ms each way. That's physics, not slow servers.

✏️ Sharpen your pencil: DNS change gone wrong

You move your website to a new server and change the DNS record. Half your friends see the new site, half the old one. Why? How could you have reduced the problem?
Answer: Old answers are still cached until the TTL expires. Before a move, lower the TTL (e.g. to 60 s) a day ahead, so caches expire quickly.

Key points
  • Data travels as small packets with source and destination IP addresses.
  • Ports pick the program on a machine; IP picks the machine.
  • DNS turns names into IPs, with caching controlled by TTL.
  • Routers forward packet by packet, hop by hop; nobody knows the whole path.
  • TCP adds reliability (order, resend); UDP trades it for speed.

IP addresses

  • Every device on a network has an IP address. IPv4: 203.0.113.7 (32 bits, ~4.3 billion, now exhausted). IPv6: 2001:db8::1 (128 bits).
  • Public addresses are reachable on the internet. Private ranges (10.x.x.x, 172.16-31.x.x, 192.168.x.x) are used inside homes/offices. NAT in your router lets many private devices share one public IP.
  • 127.0.0.1 / localhost = "this machine". Your dev servers usually listen here.
  • An IP identifies a machine; a port (0-65535) identifies a process/service on it. HTTP is port 80, HTTPS 443, SSH 22.
  • Addresses can be assigned automatically by DHCP.

DNS: the phone book

Computers route by IP, people remember names. DNS maps www.example.com → 93.184.216.34.

  1. Browser checks its cache, then the OS cache.
  2. Asks the recursive resolver (your ISP or e.g. 8.8.8.8).
  3. Resolver, if it doesn't know, asks a root server → which points to the .com TLD server → which points to the domain's authoritative name server → which returns the IP.
  4. Answer is cached for the record's TTL.
RecordMeaning
A / AAAAName → IPv4 / IPv6
CNAMEAlias to another name
MXMail servers for the domain
TXTFree text (verification, SPF)
nslookup example.com
dig example.com +short

Routing

  • A router connects networks. It looks at a packet's destination IP, consults its routing table, and forwards it to the next hop. No single router knows the full path.
  • Packets of one message may take different paths and arrive out of order; TCP reassembles them and retransmits lost ones.
  • Your device first sends traffic to its default gateway (home router) if the destination isn't local.
  • Between big networks (ISPs), BGP is the protocol that advertises which IP ranges are reachable through whom.
  • TTL in an IP packet is decremented per hop and dropped at 0, preventing endless loops.
traceroute example.com    # (tracert on Windows) see hops
ping example.com          # reachability + latency

Whole story: typing a URL

  1. DNS lookup → IP. 2. TCP connection to IP:443 (three-way handshake). 3. TLS handshake (see HTTPS). 4. HTTP request sent. 5. Packets routed across many hops to the server and back. 6. Browser renders response.
