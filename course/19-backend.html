19. Backend Frameworks: Routing, Middleware, Templates, ORMs

Module 4's raw server, with the repetitive parts handled for you.

🏭 Start here: building furniture from scratch vs a kit

A story In module 4 you wrote a web server by hand. It worked, but you had to parse URLs, set headers, handle each path with if statements, and encode every byte. Imagine doing that for 50 pages!

A framework is like a furniture kit with the frame, hinges and screws ready. You focus on what makes your app special ("what happens when someone posts an order") and the framework handles the repetitive plumbing (parsing, routing, JSON, errors, security basics).

Library vs framework: you call a library when you want. A framework calls you: you plug your code into its structure.

The journey of one request

  Request: POST /orders
     │
     ▼
  ┌─ MIDDLEWARE 1: log it ───────────────┐
  ├─ MIDDLEWARE 2: parse JSON body ──────┤   (a series of checkpoints,
  ├─ MIDDLEWARE 3: who's logged in? ─────┤    every request passes through)
  └──────────────────────────────────────┘
     ▼
  ROUTER: "POST + /orders → create_order()"
     ▼
  HANDLER (your code): validate → save to DB → build response
     ▼
  ◄── Response: 201 Created {...}   (passes back through middleware: add headers…)

1. Routing: connect URLs to your functions

from flask import Flask, jsonify, request, abort
app = Flask(__name__)

pets = {1: {"id": 1, "name": "Rex"}}

@app.get("/pets/<int:pet_id>")           # URL pattern, <int:..> captures a number
def get_pet(pet_id):
    pet = pets.get(pet_id)
    if pet is None:
        abort(404)
    return jsonify(pet)

@app.post("/pets")
def add_pet():
    data = request.get_json()
    if not data or "name" not in data:
        return jsonify(error="name is required"), 400
    new_id = max(pets) + 1
    pets[new_id] = {"id": new_id, "name": data["name"]}
    return jsonify(pets[new_id]), 201

# run:  flask run     then try:  curl localhost:5000/pets/1

Compare to module 4: no manual header-writing, no byte encoding. Same ideas, far less typing. Express (Node) looks almost identical:

app.get("/pets/:id", (req, res) => {
  const pet = pets[req.params.id];
  if (!pet) return res.status(404).json({ error: "not found" });
  res.json(pet);
});

2. Middleware: airport security for requests

Code that runs for every request before (or after) your handler: logging, checking login, rate limiting, CORS, catching crashes and turning them into clean 500 responses. Order matters: authentication must happen before handlers that need a user.

@app.before_request
def require_login():
    if request.path.startswith("/admin") and "user_id" not in session:
        abort(401)

4. ORM: objects instead of SQL

class Pet(db.Model):                       # a class = a table
    id   = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(80), nullable=False)

rex = Pet(name="Rex"); db.session.add(rex); db.session.commit()   # INSERT
dogs = Pet.query.filter_by(name="Rex").all()                         # SELECT

How to organise the code

  app/
   ├── routes/     ← HTTP stuff only: read request, return response (THIN)
   ├── services/   ← business rules: "can this coupon be used?"
   ├── models/     ← database tables
   ├── templates/  ← HTML
   └── config.py   ← settings from environment variables

Keep route handlers thin: they translate HTTP into function calls. Business logic in services is reusable and easy to test without a web server.

Brain powerYour app works with flask run on your laptop. Why isn't that good enough in production? The built-in dev server is single-purpose, not hardened or efficient for many users. Use a production server (gunicorn / uvicorn / Node cluster) behind a reverse proxy (module 16).

There are no Dumb Questions

Q: Which framework should I learn?

The one matching your language: Python → Flask/FastAPI/Django, JavaScript → Express/NestJS, Java → Spring, Ruby → Rails, PHP → Laravel. The concepts are 95% the same.

Q: What's the difference between Flask and Django?

Flask = small and flexible, you choose the parts. Django = "batteries included": ORM, admin panel, auth, forms out of the box.

Q: Where does validation belong?

At the edge of your app: check types, lengths and required fields as soon as data arrives (libraries like Pydantic or Zod help).

✏️ Sharpen your pencil: add an endpoint

Add DELETE /pets/<id> to the Flask example: return 204 if deleted, 404 if missing.
Answer:

@app.delete("/pets/<int:pet_id>")
def delete_pet(pet_id):
    if pet_id not in pets:
        abort(404)
    del pets[pet_id]
    return "", 204

Key points
  • Frameworks handle repetitive web plumbing so you write business logic.
  • Request flow: middleware → router → handler → response.
  • Routing maps method+URL to functions; middleware handles cross-cutting jobs.
  • Templates (auto-escaped) or JSON APIs; ORMs map tables to classes.
  • Keep handlers thin, config in env vars, and use a production server in production.

📋 Quick reference: the details

Key ideaA framework (Flask, FastAPI, Django, Express, Spring, Rails) provides the plumbing every web app needs, so you write only the business logic. Libraries are called by you; frameworks call your code.

The request pipeline

Request → [middleware: log, auth, parse body] → router → handler → [middleware: headers, compress] → Response
                                                           └→ database / other services

Routing: URL + method → function

# Flask
from flask import Flask, jsonify, request, abort
app = Flask(__name__)

@app.get("/users/<int:user_id>")
def get_user(user_id):
    user = db.find_user(user_id)
    if not user:
        abort(404)
    return jsonify(user)

@app.post("/users")
def create_user():
    data = request.get_json()
    if "email" not in data:
        return jsonify(error="email required"), 400
    return jsonify(db.create_user(data)), 201
// Express (Node)
app.get("/users/:id", async (req, res) => {
  const user = await db.findUser(req.params.id);
  if (!user) return res.status(404).json({ error: "not found" });
  res.json(user);
});

Middleware

Functions that run before/after handlers for every request: logging, authentication (read the session cookie, attach current_user), CORS, rate limits, error handling, compression. Order matters.

Templates vs JSON APIs

  • Server-side rendering: handler fills an HTML template (Jinja, EJS) and returns a page. Great for SEO and simple sites; templates auto-escape output (XSS protection).
  • API + SPA: server returns JSON, a JS frontend renders (module 12/13). Many apps mix both.

ORM and project layout

class User(Model):                # table → class
    id = Column(Integer, primary_key=True)
    email = Column(String, unique=True)

user = session.query(User).filter_by(email="ana@example.com").first()
  • Separate concerns: routes (HTTP), services (business rules), models (data). Handlers stay thin.
  • Validate input (FastAPI/Pydantic, Zod) at the boundary.
  • Configuration comes from environment variables, not code (module 23).
  • In production run behind a real server (gunicorn, uvicorn, Node cluster) and reverse proxy; the dev server isn't built for load.
  • Choose a mainstream, well-documented framework for your language; the concepts transfer.
