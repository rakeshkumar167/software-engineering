6. Command Line and Shell

Talking to the computer with text. Faster, scriptable, and how servers are run.

⌨️ Start here: texting with your computer

A story Clicking through folders is like pointing at things in a shop: fine for one item. But imagine telling an assistant: "Rename all 500 photos in this folder so they start with the date." Pointing 500 times is painful; a single sentence is easy.

The command line is that sentence. You type short commands; the computer answers in text. The program that listens to you is the shell.

Your map: where am I?

Folders form a tree. The shell is always "standing" in one folder, the current directory.

  /                       ← root (top of everything)
  └── Users
      └── ana                 ← your home, shortcut: ~
          ├── Documents
          │   └── notes.txt
          └── projects
              └── blog        ← YOU ARE HERE (pwd prints this)
$ pwd                 # Print Working Directory: where am I?
/Users/ana/projects/blog
$ ls                  # LiSt what's here
index.html  style.css
$ cd ..               # go UP one folder  (.. means "parent")
$ cd Documents        # go DOWN into Documents
$ cd ~                # teleport home

Pipes: the LEGO of the command line

Every command is small and does one thing. A pipe | hands the output of one to the next, like a factory conveyor belt.

  cat visitors.txt  │  sort  │  uniq -c  │  sort -nr  │  head -3
  (read the file)   → (alphabetise) → (count dupes) → (biggest first) → (top 3)
$ cat visitors.txt | sort | uniq -c | sort -nr | head -3
     41 /home
     17 /pricing
      9 /about

You just built a "top 3 most visited pages" tool from 5 tiny commands, in one line. That's the superpower.

Brain powerHow would you count how many .jpg files are in a folder? Try: ls | grep ".jpg" | wc -l: list, keep only jpg lines, count lines.

Redirect: send output somewhere else

$ ls > files.txt          # save the listing INTO a file (overwrites)
$ echo "done" >> log.txt  # APPEND to a file
$ python app.py 2> errors.txt   # send only error messages to a file

Remember module 1: every process has three channels: stdin (in), stdout (normal out), stderr (errors out). Pipes and redirects just reconnect them.

Permissions: who can touch this?

Each file has three sets of read / write / execute rights: for the owner, the group, and everyone else.

  -rwxr-xr--  ana staff  run.sh
   │└┬┘└┬┘└┬┘
   │ │  │  └─ everyone else: read only
   │ │  └──── group: read + execute
   │ └─────── owner (ana): read + write + execute
   └───────── "-" = file ("d" = directory)

"Permission denied"? Check this. Script won't run? chmod +x run.sh adds the execute right.

Danger zone: rm deletes forever (no trash can). rm -rf deletes a whole folder tree without asking. sudo means "do this as the all-powerful admin." Always re-read a command, especially one you pasted.

There are no Dumb Questions

Q: Terminal, shell, console, bash, zsh: what's what?

Terminal = the window. Shell = the program inside that understands commands (bash, zsh, PowerShell are shells). They're often used interchangeably.

Q: I typed a command and got "command not found".

Either a typo, or the program isn't in a folder listed in your PATH (the list of places the shell searches). To run a file in the current folder use ./myscript.

Q: How do I stop a running command?

Ctrl+C. Also: Tab auto-completes names and ↑ recalls old commands. Use them constantly.

✏️ Sharpen your pencil: build the commands

1) Show how many lines are in notes.txt. 2) Find lines containing "ERROR" in app.log and save them in errors.txt.
Answer: 1) cat notes.txt | wc -l (or wc -l notes.txt). 2) grep ERROR app.log > errors.txt.

Key points
  • The shell runs commands; small tools + pipes (|) combine into powerful one-liners.
  • pwd, ls, cd to move around; .. is the parent; ~ is home.
  • > overwrites a file, >> appends. Three channels: stdin, stdout, stderr.
  • Permissions are rwx for owner / group / others. chmod +x makes a script runnable.
  • Be careful with rm -rf and sudo.

📋 Quick reference: the details

Key ideaA terminal is the window; the shell (bash, zsh, PowerShell) is the program inside it that reads your commands and starts processes to run them.

Navigation and files

pwd                 # where am I?
ls -la              # list files (incl. hidden) with details
cd projects         # change directory;  cd ..  up one;  cd ~  home
mkdir demo          # make a folder
touch a.txt         # create empty file
cp a.txt b.txt      # copy        mv a.txt c.txt   # move/rename
rm b.txt            # delete (NO recycle bin!)   rm -r dir  # recursive
cat file            # print file   less file  # page through it
man ls  /  ls --help   # documentation

Paths: absolute starts with / (/Users/ana/a.txt); relative is from the current directory (../a.txt). . = here, .. = parent.

Pipes and redirection

Small tools that do one thing, chained together. Every process has stdin, stdout, stderr (module 1).

ls | wc -l                  # pipe: stdout of one → stdin of next
echo hi > out.txt           # redirect stdout to file (overwrite)
echo more >> out.txt       # append
cmd 2> errors.log           # redirect stderr
grep -r "TODO" src/ | head  # search text in files
find . -name "*.py"         # find files
cat log.txt | sort | uniq -c | sort -nr   # count duplicates

Environment variables and PATH

  • Named values passed to processes: export API_KEY=abc, read with $API_KEY.
  • PATH is a list of directories the shell searches when you type a command name. "command not found" often means it's not on PATH.

Permissions

-rwxr-xr--  1 ana staff  120 Jan 1  run.sh
 │└┬┘└┬┘└┬┘
 │ │  │  └ others: r--
 │ │  └ group:  r-x
 │ └ owner:  rwx
 └ type (- file, d directory)
chmod +x run.sh     # make executable
sudo cmd            # run as administrator (use carefully)

Handy habits

  • Tab completes, ↑ recalls history, Ctrl+C stops the running process, Ctrl+R searches history.
  • && runs the next command only if the first succeeded; exit code is in $?.
  • A shell script is a file of commands: starts with #!/bin/bash.
Caution: rm -rf and sudo don't ask twice. Read a command before pressing Enter, especially if you pasted it.
