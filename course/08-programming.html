8. Programming Fundamentals

The ideas shared by almost every language (shown here in Python).

📦 Start here: labelled boxes and a to-do list

A story Imagine a tidy storage room full of labelled boxes. One labelled age holds 21. One labelled name holds "Ana". Those boxes are variables.

Now picture a to-do list taped to the wall: "If the bin is full, take it out. For each room, vacuum. Repeat until the kitchen is clean." That's control flow.

And your friend's note "do the 'clean a room' routine" is a function: a named recipe you can reuse.

Programming is just: boxes + decisions + repetition + reusable routines.

1. Variables and types: what kind of thing is in the box?

age = 21              # whole number      (int)
price = 9.99          # decimal           (float)
name = "Ana"          # text              (str)
is_student = True     # yes/no            (bool)
tags = ["a", "b"]     # ordered list      (list)
person = {"name": "Ana", "age": 21}   # labelled pairs (dict)

Types matter because they decide what's allowed: you can multiply 21 * 2 but not "Ana" * "Bob". And "5" + "5" gives "55" (text glued), while 5 + 5 gives 10.

   age ┌────┐      name ┌───────┐     tags ┌───┬───┬───┐
       │ 21 │           │ "Ana" │          │ a │ b │ c │
       └────┘           └───────┘          └───┴───┴───┘
       int                str               list (index 0, 1, 2 ...)

2. Decisions: if / else

temperature = 31
if temperature > 30:
    print("Wear shorts")
elif temperature > 15:
    print("T-shirt is fine")
else:
    print("Bring a jacket")

The computer checks conditions top to bottom and runs the first one that's true. Indentation (the spaces) tells Python what belongs inside.

3. Repetition: loops

for fruit in ["apple", "pear", "fig"]:     # once per item
    print("I like", fruit)

count = 3
while count > 0:                           # as long as true
    print(count)
    count = count - 1
print("Liftoff!")
Infinite loop alert: if you forget count = count - 1, the condition stays true forever. Ctrl+C stops it (module 6).

4. Functions: write once, use anywhere

   input(s) ──► ┌────────────────┐ ──► output
   (parameters) │  total(prices) │     (return value)
                └────────────────┘
def total(prices, tax=0.1):       # def = "I'm defining a recipe"
    subtotal = sum(prices)
    return subtotal * (1 + tax)   # hand the answer back

print(total([10, 20]))            # 33.0
print(total([10, 20], tax=0.2))   # 36.0

Variables made inside a function are local: they vanish when it ends, like scribbles on a scrap paper.

Brain powerYou have the same 6 lines of code pasted in 4 places, and the tax rate changes. How many places must you edit? 4, and you'll forget one. Put it in one function: edit once. That's the DRY rule: Don't Repeat Yourself.

5. When things go wrong: errors

try:
    n = int(input("Age? "))
except ValueError:
    print("Please type digits only")

Rather than crashing, you catch the problem and respond kindly. Read error messages from the bottom: the last line says what, the lines above say where.

A tiny complete program

def grade(score):
    if score >= 90: return "A"
    if score >= 80: return "B"
    return "C or below"

scores = {"Ana": 95, "Ben": 82, "Cy": 60}
for student, score in scores.items():
    print(student, "→", grade(score))
# Ana → A,  Ben → B,  Cy → C or below

There are no Dumb Questions

Q: Why does 0.1 + 0.2 give 0.30000000000000004?

Computers store decimals in binary, and 0.1 can't be written exactly in binary, like 1/3 can't be written exactly in decimal. For money, store whole cents (1999) instead of 19.99.

Q: Why do lists start at index 0?

The index is the distance from the start. The first item is 0 steps from the start. You'll get used to it quickly; "off-by-one" errors are famously common!

Q: Python, JavaScript, Java: do I need to learn all?

No. Learn one well. The ideas here (variables, types, conditions, loops, functions) carry over to all of them; only the spelling changes.

✏️ Sharpen your pencil: write FizzBuzz-lite

Print the numbers 1 to 10, but print "even" instead of the number when it's even.
Answer:

for n in range(1, 11):
    if n % 2 == 0:       # % = remainder after dividing
        print("even")
    else:
        print(n)

Key points
  • Variables = labelled boxes holding typed values (int, float, str, bool, list, dict).
  • if/elif/else decide; for/while repeat.
  • Functions package reusable steps: parameters in, return value out.
  • Catch errors with try/except; read messages bottom-up.
  • These ideas are the same in nearly every language.

📋 Quick reference: the details

Key ideaA program is data plus instructions that transform it. The core tools: variables, types, conditions, loops and functions.

Variables and types

A variable is a name for a value in memory. Every value has a type which decides what you can do with it.

age = 21              # int
price = 9.99          # float (floating point: 0.1+0.2 != 0.3 exactly!)
name = "Ana"          # str
active = True         # bool
items = [1, 2, 3]     # list
user = {"name": "Ana", "age": 21}   # dict (key → value)
nothing = None        # absence of value (null in other languages)
  • Static typing (Java, Go, TypeScript): types checked before running. Dynamic typing (Python, JS): checked as it runs.
  • Mutable values can be changed in place (lists); immutable cannot (strings, numbers, tuples).
  • Scope: where a variable is visible. Variables created inside a function are local to it.

Control flow

if age >= 18 and active:
    print("adult")
elif age >= 13:
    print("teen")
else:
    print("child")

for n in [1, 2, 3]:       # iterate a collection
    print(n * 2)

count = 0
while count < 3:          # repeat while condition holds
    count += 1

Functions

Reusable, named blocks: take parameters, return a value. They let you break big problems into small ones and avoid repeating yourself (DRY).

def total(prices, tax=0.1):
    return sum(prices) * (1 + tax)

print(total([10, 20]))        # 33.0
print(total([10, 20], 0.2))   # 36.0
  • Functions should do one thing, have clear names, and ideally avoid hidden side effects.
  • Recursion: a function calling itself, needs a base case to stop.
  • Errors/exceptions: try: ... except ValueError: ... handle failure instead of crashing.

Other essentials

  • Modules/packages: import code others wrote (import json), managed with pip/npm.
  • Comments explain why; names explain what.
  • Reading error messages: the last line says what, the traceback says where.
