1. What is a Process?

A program is a file on disk. A process is that program running.

🍳 Start here: the recipe and the cook

A story You have a recipe for pancakes in a cookbook. The recipe just sits there. It can't make anything. It's only instructions.

Now you (the cook) take the recipe, get out the bowl, eggs and pan, and actually start cooking. Right now there is a cooking-in-progress: ingredients half mixed, the pan hot, you on step 3 of 7.

That's the difference: the recipe is a program. The cooking-in-progress is a process.
  PROGRAM (on disk)               PROCESS (running)
  ┌──────────────────┐   start    ┌──────────────────────────┐
  │  chrome.exe      │ ─────────► │ PID 4821                 │
  │  (just a file)   │            │ memory: tabs, history... │
  │  instructions    │            │ currently on: step 17    │
  └──────────────────┘            └──────────────────────────┘

Two cooks, one recipe

Open Chrome twice. Same recipe, two cooks, two kitchens. Each process gets its own PID (Process ID, like an order number) and its own memory. If one catches fire (crashes), the other kitchen keeps cooking. That's the whole point of a process: isolation.

Brain powerYour laptop has 8 CPU cores but shows 300 running processes. How can 300 things "run at once" on 8 cores? (Think of one chef quickly switching between 300 pots, giving each a few milliseconds. The OS "scheduler" is that chef. It happens so fast you can't see it.)

The life of a process

  born ──► READY ──► RUNNING ──► WAITING ──► READY ...
  (a parent          ▲    │        (for disk, network,
   started it)       │    ▼         keyboard)
                     └─ scheduler swaps it out
                                    │
                                    ▼
                               DIED (exit code 0 = "all good")

Every process has a parent that started it. When you type python app.py in the terminal, the shell (parent) starts a Python process (child).

Try it right now (2 minutes)

$ sleep 300 &          # start a process that does nothing for 5 minutes
[1] 52311                # ← its PID
$ ps | grep sleep        # find it
$ kill 52311             # end it (use YOUR number)

You just created and killed a process. A web server is exactly the same, except instead of sleeping it waits for visitors.

There are no Dumb Questions

Q: Is a process the same as an "app"?

Close, but one app can use several processes (Chrome uses many). "App" is what users see; "process" is what the OS tracks.

Q: What if I close the window, does the process die?

Usually yes, but not always. Background services keep running with no window. That's why servers can run without anyone logged in.

Q: What's a thread then?

One cook with several pairs of hands. Threads are workers inside one process, sharing the same kitchen (memory). Faster to start, but two hands grabbing the same salt can collide (bugs!).

✏️ Sharpen your pencil: which are programs, which are processes?

(a) /usr/bin/python3 sitting on your disk, (b) the Spotify window playing music, (c) a file named server.js, (d) PID 9012 using 200 MB RAM.
Answer: programs = (a), (c) (code files). Processes = (b), (d) (running things). Note: server.js is source code; it becomes a process only when node server.js runs it.

Key points
  • Program = instructions on disk. Process = program running.
  • Each process has its own PID and private memory.
  • The OS scheduler switches between processes so fast that they seem simultaneous.
  • Web servers are just processes that wait for requests.

📋 Quick reference: the details

Key ideaA process is a running instance of a program, with its own memory, its own state, and a unique ID (PID) handed out by the operating system (OS).

Program vs process

ProgramProcess
Passive: a file (e.g. chrome, python, server.js)Active: that file loaded into memory and executing
One copy on diskMany processes can come from one program (open two terminal windows)

What the OS gives each process

  • PID: unique number identifying it.
  • Own memory space: one process cannot normally read another's memory (isolation). Roughly: code, a stack (function calls, local variables) and a heap (dynamically allocated data).
  • CPU time: the OS scheduler rapidly switches between processes so many appear to run at once.
  • Resources: open files, network sockets, environment variables, a working directory.
  • Standard streams: stdin, stdout, stderr.

Lifecycle

Created (usually by another process: a parent starts a child) → ready → running → waiting (e.g. for disk or network) → terminated with an exit code (0 = success by convention).

Threads

A process can contain several threads: independent flows of execution that share the process's memory. Threads are cheaper than processes but sharing memory makes bugs (race conditions) easier.

Try it

ps aux | head        # list processes
echo $$              # PID of your current shell
top                  # live view (q to quit)
sleep 100 &          # start a background process
kill <PID>           # ask it to stop
Why it matters for web development: a web server is just a long-running process that waits for network requests. If the process crashes, the site is down. "Restart the server" literally means "kill the process and start a new one".
