12. HTML, CSS, JavaScript and the DOM

What the browser does with the response your server sent.

🏠 Start here: building a house

A story A web page is like a house:
🧱 HTML = the structure: walls, doors, rooms ("this is a heading, this is a button, this is a list").
🎨 CSS = the decoration: paint colours, furniture layout, curtains.
⚡ JavaScript = the electricity: lights that switch on, doors that open when you press a button.

Three languages, three jobs. Mix them up and things get messy.

Step 1: HTML, the skeleton

HTML uses tags in pairs: an opening tag, content, a closing tag.

<h1>Ana's Pizza</h1>                    <!-- big heading -->
<p>Best slices in town. <a href="/menu">See menu</a></p>
<ul>
  <li>Margherita</li>
  <li>Pepperoni</li>
</ul>
<img src="pizza.jpg" alt="A hot pizza">     <!-- alt text helps screen readers -->
<button id="order">Order now</button>

Tags nest like boxes in boxes. That nesting forms a tree:

  html
  ├── head
  │    └── title
  └── body
       ├── h1 "Ana's Pizza"
       ├── p ── a "See menu"
       ├── ul ── li, li
       └── button "Order now"      ← this tree is called the DOM

Step 2: CSS, the paint

A CSS rule says which things (selector) get which look (properties).

h1 { color: tomato; font-family: Georgia, serif; }   /* every h1 */
.special { background: gold; padding: 8px; }          /* anything with class="special" */
#order:hover { background: darkred; }                 /* the button, when hovered */

The box model: every element is a box with content, padding (inside cushion), border, and margin (outside gap):

  ┌──────────── margin ──────────────┐
  │ ┌────────── border ────────────┐ │
  │ │ ┌──────── padding ─────────┐ │ │
  │ │ │        CONTENT           │ │ │
  │ │ └──────────────────────────┘ │ │
  │ └──────────────────────────────┘ │
  └──────────────────────────────────┘

For layout, use Flexbox (row or column of items) and Grid (rows and columns). Media queries make a page adapt to phones: @media (max-width: 600px) { ... }.

Step 3: JavaScript, make it alive

const button = document.getElementById("order");     // find the element in the DOM
button.addEventListener("click", function () {       // when clicked...
  document.querySelector("h1").textContent = "Thanks for ordering!";   // ...change it
});

That's it: find an element → listen for an event → change something. Nearly every interactive website is variations on this idea.

Fetch: talking to the server without reloading

button.addEventListener("click", async () => {
  const response = await fetch("/api/menu");     // HTTP request (module 4!)
  const items = await response.json();           // parse JSON (module 11!)
  document.querySelector("ul").innerHTML = "";
  for (const item of items) {
    const li = document.createElement("li");
    li.textContent = item.name;                  // textContent is safe from XSS
    document.querySelector("ul").appendChild(li);
  }
});
Brain powerYou can try all of this right now: open any web page, press F12, click the Console tab and type document.body.style.background = "pink". You just changed the page's DOM live. (Only on your screen; reload and it's gone.)

Putting it together: a complete page

<!doctype html>
<html>
<head>
  <meta charset="utf-8"><title>Counter</title>
  <style> button { font-size: 1.5rem; padding: 8px 16px; } </style>
</head>
<body>
  <h1>Clicks: <span id="n">0</span></h1>
  <button id="btn">Click me</button>
  <script>
    let count = 0;
    document.getElementById("btn").addEventListener("click", () => {
      count++;
      document.getElementById("n").textContent = count;
    });
  </script>
</body>
</html>

Save it as counter.html and double-click it. You've built a web app.

There are no Dumb Questions

Q: Do I need React / Vue to build a site?

No. Learn plain HTML/CSS/JS first. Frameworks automate the "update the DOM when data changes" chore, and make sense once you've felt that chore yourself.

Q: Is JavaScript the same as Java?

No, unrelated. (Naming was a 1990s marketing decision.)

Q: Why use <button> instead of a styled <div>?

Semantic tags give free keyboard support, accessibility for screen readers, and meaning to search engines.

✏️ Sharpen your pencil: who does what?

HTML, CSS or JS? (1) turn the heading red, (2) show a popup when a form is submitted, (3) add a "Contact us" link, (4) put items in two columns.
Answer: (1) CSS, (2) JS, (3) HTML, (4) CSS (flexbox/grid).

Key points
  • HTML = structure, CSS = style, JS = behaviour.
  • The browser turns HTML into a tree (the DOM) that JS can read and change.
  • JS pattern: find element, listen for event, change the DOM.
  • fetch calls the server and updates the page without reload.
  • Use semantic tags and textContent for safe, accessible pages.

📋 Quick reference: the details

Key ideaThree languages, three jobs: HTML = structure and content, CSS = presentation, JavaScript = behaviour. The browser turns HTML into a live tree called the DOM.

HTML

<!doctype html>
<html lang="en">
  <head><meta charset="utf-8"><title>My page</title>
        <link rel="stylesheet" href="style.css"></head>
  <body>
    <h1>Hello</h1>
    <p class="intro">A <a href="/about">link</a>.</p>
    <button id="btn">Click</button>
    <script src="app.js"></script>
  </body>
</html>
  • Elements are tags with attributes (href, class, id). Use semantic tags (header, nav, main, article, button) for accessibility and SEO.
  • Forms: <form method="post" action="/login"> sends an HTTP request (module 4) when submitted.

CSS

.intro { color: #333; font-size: 1.2rem; }
button:hover { background: royalblue; }
@media (max-width: 600px) { body { padding: 8px; } }   /* responsive */
  • Selectors pick elements (tag, .class, #id); cascade + specificity decide which rule wins.
  • Box model: content → padding → border → margin.
  • Layout: Flexbox (one dimension), Grid (two dimensions). Responsive design adapts to screen size.

JavaScript and the DOM

The DOM (Document Object Model) is the page as a tree of objects that JavaScript can read and change.

const btn = document.getElementById("btn");
btn.addEventListener("click", () => {
  document.querySelector(".intro").textContent = "You clicked!";
});

// Fetching data without reloading the page
const res = await fetch("/api/users/1");
const user = await res.json();
  • Events (click, input, submit) trigger your functions.
  • fetch makes HTTP requests from the page (AJAX); this is how single-page apps update without reloads.
  • Frameworks (React, Vue, Svelte) manage DOM updates declaratively from your data.

How the browser renders

  1. Receive HTML → parse to DOM. 2. Discover CSS/JS/images → request them. 3. Build styles, compute layout. 4. Paint. 5. JS can change the DOM at any time → re-layout/paint.
Try it: open any page, right-click → Inspect. Edit text in Elements; watch requests in Network. Changes are local to your browser only.
