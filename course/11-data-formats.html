11. Files, Encodings and Data Formats

Everything is bytes. Formats and encodings are agreements on what the bytes mean.

🔤 Start here: secret decoder ring

A story You and a friend agree: "A=1, B=2, C=3..." You send 8 9. Your friend decodes: "HI". The message is just numbers; the agreement about what the numbers mean makes it text.

Computers store everything, whether text, photos or songs, as bytes (numbers 0 to 255). A file format or encoding is the agreement about what those numbers mean. If two sides disagree, you get garbage, like using the wrong decoder ring.

Text is just numbers with a decoder ring

  The letter  "A"  →  number 65  →  bits 01000001
  The letter  "a"  →  number 97
  The emoji   "😀"  →  number 128512 (Unicode code point)

  Encoding = how those numbers become BYTES on disk. UTF-8 is the common one:
     "A"  → 1 byte     [41]
     "é"  → 2 bytes    [C3 A9]
     "😀" → 4 bytes    [F0 9F 98 80]

Unicode = the giant catalogue giving every character in every language a number. UTF-8 = the most popular way to write those numbers into bytes. Always use UTF-8.

The mojibake mystery: you see cafÃ© instead of café. The bytes were written as UTF-8 but read with a different decoder ring. Fix: make both sides say "UTF-8" explicitly: open("f.txt", encoding="utf-8") and Content-Type: text/html; charset=utf-8.

Formats for structured data

Say you want to send a person's details between programs. You need a shared way to write it down:

// JSON: the web's favourite
{ "name": "Ana", "age": 21, "languages": ["en", "hi"], "student": true }

# CSV: simple table, spreadsheet-friendly
name,age
Ana,21
Ben,25

<!-- XML: older, wordier -->
<person><name>Ana</name><age>21</age></person>

# YAML: human-friendly config
name: Ana
age: 21

JSON rules to remember: keys and strings in double quotes; no trailing commas; no comments; values are string, number, boolean, null, array, or object.

Serialisation: packing for the trip

Your program holds objects in memory. To save them or send them over the network, you must flatten them into text/bytes (serialise), and rebuild on the other side (deserialise). Like flat-pack furniture.

import json
user = {"name": "Ana", "age": 21}
text = json.dumps(user)          # object → text: '{"name": "Ana", "age": 21}'
back = json.loads(text)          # text → object again
print(back["name"])              # Ana

# Saving to and reading from a file
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(user, f)
with open("user.json", encoding="utf-8") as f:
    loaded = json.load(f)
Brain powerThe string "naïve" has 5 characters. Roughly how many UTF-8 bytes? 6: every ASCII letter is 1 byte but "ï" takes 2. Characters ≠ bytes!

There are no Dumb Questions

Q: Does renaming photo.png to photo.txt change it?

No. The extension is only a hint to the OS about which program to open. The bytes are the same. Real formats identify themselves with "magic bytes" at the start.

Q: Why JSON and not CSV for APIs?

JSON handles nesting (a person with a list of addresses) and types. CSV is flat, like one spreadsheet table.

Q: Is it safe to load any data a stranger sends me?

JSON is safe to parse, but always validate it (right fields? right types? sensible size?). Some formats (like Python's pickle) can run code when loaded; never load those from untrusted sources.

✏️ Sharpen your pencil: spot the invalid JSON

Which are invalid? (a) {'name': 'Ana'} (b) {"name": "Ana",} (c) {"age": 21} (d) {"tags": [1, 2, 3]}
Answer: (a) single quotes are not allowed, (b) trailing comma not allowed. (c) and (d) are valid.

Key points
  • Everything is bytes; formats and encodings give them meaning.
  • Use UTF-8 everywhere; mismatched encodings cause garbled text.
  • JSON = the common web data format; CSV for flat tables; YAML for config.
  • Serialise to save/send, deserialise to rebuild. Always validate incoming data.

📋 Quick reference: the details

Key ideaA file is a named sequence of bytes. A format says how to interpret them (JSON, PNG, PDF). Text needs an encoding to map characters to bytes.

Text vs binary

  • Text files: bytes that decode to readable characters (source code, JSON, CSV, HTML). Human-editable, diff-friendly.
  • Binary files: structured bytes for programs (images, executables, databases, zip). Compact; need the right program to read.
  • The extension (.png) is only a hint; formats usually start with identifying "magic bytes".

Character encodings

  • ASCII: 128 characters (English letters, digits, symbols), 1 byte each.
  • Unicode: a catalogue giving every character in every language (and emoji) a number (code point).
  • UTF-8: the dominant encoding of Unicode. 1 to 4 bytes per character; ASCII-compatible. Use it by default everywhere.
  • Wrong encoding assumed → mojibake: "cafÃ©" instead of "café". Be explicit: open(path, encoding="utf-8"), Content-Type: text/html; charset=utf-8.
  • Number of bytes ≠ number of characters: "é" is 2 bytes in UTF-8, "😀" is 4.

Serialisation

Serialising turns in-memory objects into bytes/text to save or send; deserialising reverses it.

import json
text = json.dumps({"name": "Ana", "age": 21})   # object → string
data = json.loads(text)                          # string → object
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(data, f)
Never trust incoming data: validate it. Malformed JSON, huge files and unexpected types are normal on the internet. Also, never deserialise untrusted data with formats that can execute code (e.g. Python pickle).
